Option 1 — Tree sidebar

Recommended

Projects become collapsible groups and agents become their children, so the hierarchy is visible in one 270px rail. This removes both the repeated AGENTS | TRACES button grid and the second sidebar while keeping lifecycle state close to the project. Best balance: materially less navigation friction without changing Observatory’s project-first mental model.

Option 2 — Flat global views, project = filter

Agents and traces become global inventories; project is a filter chip and a column instead of the top-level navigation boundary. Project lifecycle controls move into a dedicated Projects view. Best at scale and easiest to scan across harnesses, but it is the biggest rebuild and deliberately demotes lifecycle management.

Option 3 — Project dropdown + single contextual sidebar

A project picker moves into the header and the one remaining sidebar shows agents for only that project; AGENTS / TRACES stays as a local segment. This is the cheapest change and removes the double-sidebar layout. Weakest fix: agents in the other three projects remain hidden until the operator changes context.

Trace segmentation — sessions, runs, and one-shots

Container sessions become expandable parents, so a multi-agent workflow reads as one event with its runs nested underneath. Standalone TUI runs have no containing session, so they stay at the top level under their agent name. Switching to agent grouping answers the inverse question: what has this agent done across sessions?
